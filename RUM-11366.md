[C++] Implement RUM feature with do-nothing API

Add a `features/rum` module to the SDK, defining a `Feature` that can be registered on SDK to enable RUM support.

D.o.D.

- `datadog/rum.h` defines the types and functions required to configure and enable RUM via the C API
- `datadog/rum.hpp` defines the same for the C++ API
- `impl/features/rum/` contains a `Feature` implementation for RUM which exposes no useful functionality
- Example programs register RUM

## Questions

1. **RUM Configuration**: What configuration options should be exposed in the initial "do-nothing" API? Should we include session timeout, sampling rate, application ID, etc. even though they won't be used yet?
   
2. **Feature ID**: What 4-character FourCC should we use for RUM? "RUMS" seems appropriate, but we should verify it's unique.

3. **API Scope**: Should the initial API include placeholder functions for sessions, views, and actions, or should it be truly minimal with just feature registration?

4. **Error Handling**: Should RUM initialization return success/failure indicators like logging, or should it follow a different pattern?

5. **Thread Safety**: Should we implement thread-safe state management from the start, or can that wait until we have actual state to manage?

## Implementation

### Step 1: Create RUM Feature Implementation Structure
- Create directory `src/impl/features/rum/`
- Create `src/impl/features/rum/rum.hpp` with basic `Rum` class inheriting from `Feature`
- Create `src/impl/features/rum/rum.cpp` with minimal implementation
- Create `src/impl/features/rum/types.hpp` for RUM-specific types (initially empty)

### Step 2: Implement C API Header
- Create `include-c/datadog/rum.h`
- Define `dd_rum_t` opaque struct type  
- Define `dd_rum_config_t` configuration struct with basic fields
- Define functions:
  - `dd_rum_config_create()` / `dd_rum_config_destroy()`
  - `dd_rum_init(dd_core_t*)` / `dd_rum_destroy(dd_rum_t*)`
- Follow exact patterns from `logging.h` for consistency

### Step 3: Implement C++ API Header  
- Create `include-cpp/datadog/rum.hpp`
- Define `RumConfig` configuration struct
- Define `Rum` class with static `Register(Core&)` method
- Follow exact patterns from `logging.hpp` for consistency

### Step 4: Implement C API Bindings
- Create `src/c/rum.cpp`
- Implement all functions declared in `rum.h`
- Use same patterns as `src/c/logging.cpp` for memory management and error handling
- Create bridge between C structs and C++ implementation

### Step 5: Implement C++ API Bindings
- Create `src/cpp/rum.cpp`  
- Implement `Rum` class methods
- Bridge to internal `impl::Rum` implementation
- Use same patterns as `src/cpp/logging.cpp`

### Step 6: Update Main Headers
- Add `#include "datadog/rum.h"` to `include-c/datadog.h`
- Add `#include "datadog/rum.hpp"` to `include-cpp/datadog.hpp`

### Step 7: Update Examples
- Modify `examples/c/main.c` to register RUM feature after logging
- Modify `examples/cpp/main.cpp` to register RUM feature after logging
- Add error handling for RUM registration failures

### Step 8: Add Basic Tests

- Create `tests/cpp/rum_cpp_api_test.cpp` for C++ API tests  
- Test basic feature registration and initialization
- Follow patterns from existing logging tests
